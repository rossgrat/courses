Algorithms Mastery Course | 3
1. Mission and target learner
Target: solve unfamiliar LeetCode Hard problems correctly in 45 minutes or less. Use Go first, with
selected C++ and Rust practice. Choose your session duration. Advance by skill, without stage deadlines.
See sections 24-25 for languages and session planning.
"Any Hard" is the long-term ambition. The course measures progress on broad, unseen samples; no
finite benchmark can certify every problem.
2. How the curriculum works
Tell the tutor your available study minutes before each session. The tutor asks if you omit the duration.
Split ordinary study into retrieval, focused work, and feedback using section 25. Timed assessments keep
their stated limits and a separate review period.
Day
Main work
Monday
Study one small idea and explain a worked example.
Tuesday
Close the resource; reconstruct, implement and test.
Wednesday
Solve a related problem with help only when needed.
Thursday
Change a constraint or solve another application.
Friday
Revisit older material and attempt mixed, unlabeled problems.
The problem-solving loop
Model: restate constraints, try tiny cases and write a brute-force baseline.
Derive: identify useful structure; define state and why each step is safe.
Implement: write the solution yourself.
Verify: test boundaries and compare with a simple independent solver where feasible.
Explain: give the correctness argument, time/space cost and key assumptions.
Teaching and feedback
The tutor plans each lesson around an independent result and its place in the course. The plan includes a
demonstration, supported practice, a different application, success criteria, and a stopping rule.
The tutor demonstrates how to choose an approach and supporting claims. A finished solution alone does
not show these decisions. For proofs, start from the exact target, identify the required facts, and connect
them into a whole argument.
Help decreases as you practice. Study a demonstration, try a related task with limited help, then attempt a
different task without conceptual prompts. Short sessions can cover part of this sequence. Return after a
delay to test independent application.
Questions diagnose a specific gap. The tutor accepts sufficient reasoning without requiring preferred
wording. After two unsuccessful prompts on one gap, the tutor explains directly or changes the example.
This is a teaching safeguard, not a research-derived threshold.
Feedback identifies a missing premise, invalid inference, failing case, or implementation defect in the
whole work. During independent ordinary practice, request a small hint after 15-25 minutes without
progress. Use about half the focused block when it is shorter. Request help earlier when needed.

Keep spaced retrieval near 15-25 percent of study time. Select useful reviews within that budget. A due

problem-solving.

Prompted agreement and repeated paraphrases do not establish independent construction. After two
teaching sessions on a repair, compare independent output and help required. If progress stalls, change
the instruction or task scope.

are on section 27.

4. Stage 0 - Baseline and setup
Objective
identify whether your main gaps are mathematical reasoning, algorithm selection, implementation or
speed.
Set up once
Start in a Go workspace with tests and a scratch file. Review slices/aliasing, maps, sorting comparators,
heaps, queue indices, bytes/runes, recursion depth and integer bounds. Build core structures once, then
use permitted library tools.
For selected exercises, compare the efficient algorithm against a simple brute-force solver on small
generated inputs. Go fuzzing is optional. Tests complement the correctness argument.

Start the first learning cycle
Read a short explanation of your weakest foundational idea. Trace one example, close the material,
implement it and solve a related problem. Return after a delay and reconstruct it without notes.
Use one explanation source at a time. MIT supplies foundations; The Algorithm Design Manual (ADM) is a
practical reference. Use the advanced sources only for the stage you are studying.
Progression rules
Complete the build task, practice ladder and exit criteria for each stage, then use the shared gate on
section 22. Split broad stages into smaller units. Skip familiar material only after an independent check.
A Hard exercise early in the course is a learning target. Learn to derive and implement it before
demanding a 45-minute solve. Keep sessions bounded; resume tomorrow when necessary.
Keep the baseline in Go. Add C++ and Rust through selected practice, as described on section 24.
